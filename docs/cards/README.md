# Cards Docs

Cards is a separate product area. Its bot, future web UI, and any customer-facing API must be planned separately from Numbers.

## Active Decision

Cards should eventually have:

- a dedicated web surface,
- an API suitable for internal automation and future external integrations,
- Telegram bot flows as one client of that API.

## Current Docs

- `PHONE_VERIFICATION_CONCEPT.md`: future cards-only phone verification concept.
- `legacy/BLUEPRINT_CHECKLIST.md`: old Cards Bot implementation checklist kept for reference.

## Current Priority

Cards is not the immediate API consolidation target. Use the legacy checklist only when we explicitly resume Cards work.
